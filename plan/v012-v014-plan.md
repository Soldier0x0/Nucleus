# Roadmap: v0.12 · v0.13 · v0.14

Planning document for the next three waves, agreed October 2026. New rule for this arc: **merge
versions into waves** — the user does not want many small versions. One PR = one version, the same
ship policy as before (green CI → publish → user tests on device after).

Companion documents:
- `plan/design-system.md` — tokens, bento rules, widget guidelines.
- `plan/design/*.html` + `plan/design/shots/*.png` — visual boards for every surface described here.

## v0.12 — Phone & Sync

**Theme:** the release that makes the phone feel *finished* and *invisible-ly backed up*, plus the
platform bits users can see on the home screen.

### 1. Invisible sync
Triggers (all silently, no toasts anywhere in the app, this is decided):
- on unlock / app foreground
- 2–3 min timer while app open
- on change (right after a write)
- on Wi-Fi join
Failures stay silent: backoff for the timer, never pop anything in your face. No toasts, ever.
The only surfaced state is the mini **sync pill** next to the online indicator on home.

### 2. Sync pill (beside online indicator)
- **green** = synced (all devices current)
- **period-style amber** = connected but not current (off network / partner device unseen)
- **red** = last attempt failed ≥ 24h ago → brow-furrow state
- tap = sync now; long-press = open sync screen
- icon only appears when a desktop is paired (nothing before that)
- no toasts, no banners, no popups. Icon + silent failure modes.

### 3. Reverse freshness
- Desktop is always the server, phone is the client: **freshness = already synced by the time you
  unlock**, i.e. "reverse freshness" (on unlock you see it already there).
- Mobile Offline rule (locked): closed app = nothing goes out of the app — nothing transmitted
  while closed, no background radios, no cloud. Closed app = 0 external egress.
- Mention "Phone last seen 2m ago" chips on desktop.

 "Phone last seen" chip + reverse freshness wording on the desktop boards.

### 4. IA overhaul
- Cold start lands on **Favorites** (the 4-tab sugar: Favorites · Today · Attention · Settings).
- Home screen name tap and Settings→Profile both reach Profile.
- 9 drawer groups approved:
  Money · Vehicle · Home · Life · Health (+ Cycle under Health on **desktop** only) · Travel ·
  Media · Documents & Notes · Tools
- 4 tabs: **Favorites · Today · Attention · Settings** — delete ReopenOnce/takePendingReopen
  machinery (warm resume keeps last screen; cold start = Favorites).

### 5. Wiki + emergency card
- Wiki: **delete** is allowed (was read-only-ish).
- Emergency card: **hard delete** (no recycle bin semantics).

### 6. License truth
- Proprietary notice for own code; third-party notices stay unchanged; repo LICENSE reflects this.

### 7. Design tokens, motion, microcopy
- Tokens are described in `plan/design-system.md`; applies to phone + widgets here, desktop-wide
  1.0 comes in v0.14.
- Motion: 150–300ms ease-out, no bounce; skeletons and empty states; microcopy in the friendly
  human voice (e.g. "Nothing wants you. Go live your life.").

### 8. Cheap security wins
- block `READ_MEDIA_IMAGES` on the picker (we do not need it; camera only)
- `allowBackup=false`, FLAG_SECURE on every screen containing papers
- clipboard auto-clear, and the v0.13 DB encryption is *not* here (it is v0.13)

### 9. Fuel rework (locked model)
- 3 tank-state taps: **"To my usual full" / "Was empty before this" / "Partial"** (default partial).
- optional level chips (Reserve/¼/½/¾) learn usable capacity per ride.
- 3 inputs ₹ + litres + ₹/L — any two derive the third + cross-check enforced
  (repair prompt if mismatch).
- Money is always exact; mileage only across two anchors: brim→brim or empty→brim/empty.
- Odometer optional, **type-while-viewing** photo sits above fields (photo first, fields below).
- Partials and 1L emergency cans count litres toward the cycle, distance only across anchors.
- "Missed a fill?" plausibility flag when the ladder doesn't converge.
- No OCR writes data. (Future: segment-detection suggestions, Dev Lab gated, judged on real photos.)
- Amount often auto-captured from UPI payment notifications
  (BIND_NOTIFICATION_LISTENER_SERVICE is already in the shipped APK).
- `vehicleMath.ts` (line 43) already does anchor-based cycle distance; extend, don't replace.

### 10. Station finder
- Data: OpenStreetMap (`amenity=fuel` + brand tags) fetched once per city area, cached ~20 last
  stations offline.
- COCO isn't public data → **user-tagged COCO + favorites** sort first, then nearest.
- Google Maps opens **route preview to the pin**, not auto-started nav.
- Per-station own-price history + mileage-per-station analytics in v0.13 (history wave).

### 11. Android home-screen widgets (IN this version)
- Library: **`react-native-android-widget` (0.22.1)** — active, Expo config plugin, widgets are
  JSX-rendered (see research note in design-system doc).
- Delivered widgets (visuals on `plan/design/android-widgets.html`):
  - **2×2 "Attention"** — count, top overdue item, tap = jump to Attention.
  - **4×2 "Attention + Fuel"** — overdue/due-soon rows + fuel cycle stats (km in cycle, ₹/L avg).
- Light/dark follow system; Material-You dynamic color is a stretch goal **not** in v0.12.
- v0.12 changelog must contain a Widgets bullet (changelog-matches-reality rule).

## v0.13 — History & Trust

**Theme:** the release that makes data feel *owned* and durable: Git-like journal + encryption.

### 1. Change journal
- Every mutation appends `{time, device, module, record, before→after}`.
- Sync batches reference journal entries (dedupe by device clock + record id).
- Per-record History screen (GitHub-like), per-record **revert** to any state.
- **Restore deleted** records from History (like GitHub's restore).
- Timeline screens upgrade to read from the journal (true "what happened when").

### 2. Full DB encryption + Keystore
- SQLCipher-style whole-DB encryption; key in Android Keystore (StrongBox if available),
  desktop key in OS keychain (libsecret/Credential Manager).
- Phone↔desktop sync keys: TOFU pinning audit (pin on first pairing; alert on change).

### 3. PIN rate limiting (brute-force defense)
- Exponential backoff after N wrong PINs (documented thresholds).

### 4. Clipboard hygiene
- Auto-clear copied secret-ish values (card numbers, OTPs) after 60–90s.

### 5. Sync key-pinning (TOFU) audit
- Re-audit the TOFU path after v0.12 carves the sync lanes wider.

## v0.14 — Desktop, complete

**Theme:** "not a projection of the phone, but a full-fledged workspace" with Apple-grade look and
feel. Reference apps: Linear, Arc, Amie (primary); user's own refs Wintoys + Zen Browser secondary.

### 1. Shell
- Bento Today (+ Attention as first-class sidebar item and Ctrl+K palette) — the `desktop.html`
  board is the target look.
- Two-pane nodes; sidebar groups = the 9 approved groups; Attention badge count.
- **Multi-window** (locked): Tauri native `WebviewWindow` — a record can be popped out.
- Tray icon, notifications, autostart.

### 2. Modules parity
- Money, Vehicle (fuel rework + station finder desktop UI), Home, Travel, Media.
- **Cycle sits under Health on desktop too** (though phone IA changed, decision is desktop-only IA).
- Health (+ Cycle) then Media fill the sidebar list.

### 3. Desktop-specific features
- Drag-drop import (files/folders → matching modules).
- Print / PDF export for lists, records, timelines.
- Saved views (filter sets with names).
- **In-app document viewers** — pdf.js in-app (today desktop hands off to system apps via
  `openPath`); phone already has in-app viewers (`react-native-pdf` 6.7.7, `DocViewer.tsx`).
- Dev Lab (hidden dev tools screen, also future home for OCR segment-detection experiments).
- tauri-plugin-updater (signed) — behind a flag until proven.

### 4. Desktop theme
- First-launch = **follow system, and ask the user to choose**.
- Warm Paper tokens per `plan/design-system.md`.

### 5. Widgets (post-v0.12 continuity)
- Android widgets stay maintained in every later version (Material-You dynamic color is the
  follow-up), even though their introduction happened in v0.12.

## Cross-cutting rules

- **Changelog bullets start with Fixed/Added/Changed** (CI enforces; see
  `.github/scripts/release-notes.test.js`).
- **Changelog must match reality** — only claim what ships in that version (the widgets bullet).
- One PR per version. Ship policy: green CI → publish release → user tests on device →
  sub-versions fix fast (e.g. v0.12.1 style).
- Guardrail files are untouchable without explicit user sign-off:
  `paperViewerPath.ts`, `paperViewerUri.ts`, `documentViewerCopy.ts`, `v095.test.ts`,
