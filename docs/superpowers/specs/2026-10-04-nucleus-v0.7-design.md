# Nucleus v0.7 design

Date: 2026-10-04

Status: plan only. Do not implement from this file.

The four groups below are one version and one later implementation pull request. They are not split into separate plans.

## Goal

Ship v0.7 as one release: remove leftover demo money, make every home board a two-column circle, separate public transport from a personal vehicle, and add the cycle, gallery, and privacy surfaces listed below.

## Global Constraints

- One release, v0.7. Do not rewrite v0.6, v0.6.1, v0.6.2, or v0.6.3 notes. Do not pre-seed the next version.
- The user can be anyone. Do not write copy that assumes she.
- No foods, remedies, mood or arousal forecasts, spoken buddy, points, or guilt words (overdue, missed, behind, late, fail).
- Tests must use an upgraded database that has no sampleIds, and a real icon alias change. A fresh withSampleData test is not enough.
- Install over the current app. Do not uninstall.
- User's real data that must survive: income 2000, expense 177, expense 100, and their own naked bike. Demo leftovers must go: Activa fuel and service money copies (notes like "Activa · 5.6 L" and "Activa · Engine oil"), the 45000 demo budget, and unnamed "Two Vehicle expenses on a date" lines.

## Starting tree

Implement on the tree that already contains v0.6.3. That tree has `withoutSampleData` in `frontend/src/core/sample.ts`, `settings.sampleIds` and `settings.sampleBudget` on `Settings` in `frontend/src/core/types.ts`, and `askOnRelaunch` in `frontend/src/core/lockPolicy.ts`. This design does not rewrite those releases.

## Icon restart

A real icon change still restarts the app. An unlocked phone does not ask for the thumbprint.

There is no change that stops Android from killing the process on a launcher-alias change. `launcherIconChange` in `frontend/src/core/launcher.ts` still returns `changed: true` when the enabled alias is not the next alias. `NucleusAndroidModule.kt` still calls `setComponentEnabledSetting` for that change. `askOnRelaunch({ lockEnabled: true, marked: true, phoneLocked: false, fullyClosed: false })` stays `false`. A locked phone, or a full close, still asks. Do not edit `frontend/modules/nucleus-android/android/src/main/java/com/nucleus/widgets/NucleusAndroidModule.kt` to keep the process alive.

The v0.7 test file proves this with a real alias change from the manifest default `IconPaperPaper` to `IconMetalDune`, on an upgraded database whose `sampleIds` is `[]`. It does not call `withSampleData`.

## Group 1 — leftover demo

`fuel.added` and `service.added` in `frontend/src/core/actions.ts` write money rows even after the vehicle row is gone:

- Fuel note: `` `${vehicleName} · ${litres} L` ``, category `Fuel`. `vehicleName` is the vehicle name, or `"Vehicle"` when that id is already missing.
- Service note: `` `${vehicleName} · ${SERVICE_LABEL[kind]}` ``, category `Vehicle`. The labels are `General service`, `Engine oil`, `Tyres`, `Battery`, `Brakes`, `Repair`, and `Maintenance`.

`withoutSampleData` today drops `sampleIds` or the legacy Activa / Swift fingerprints. It does not drop a mirror whose note is `Activa · 5.6 L` or `Activa · Engine oil` when `sampleIds` is `[]` and no Activa vehicle remains.

v0.7 deletes an expense when its note matches that fuel or service shape and no current vehicle has that name. A mirror whose vehicle is still in `db.vehicles` stays, including a fill on the user's own bike. Income `2000`, expense `177`, expense `100`, and the vehicle with `body: "naked"` stay. Links that point at a deleted mirror are dropped by the existing `dropSampleRows`.

The demo budget is exactly `{ monthly: 45000, categories: { Food: 6000, Shopping: 4000 } }`.

- When the current budget is that object and `settings.sampleBudget` is set, put `sampleBudget` back and clear `sampleBudget`.
- When the current budget is that object and `sampleBudget` is absent, replace it with `{ monthly: 0, categories: {} }`.
- When the current budget is any other object, leave it.

`dataHealth` in `frontend/src/core/life.ts` keys duplicates by date, amount, and category, and titles them `Two ${category} expenses on ${date}`. v0.7 keeps that key and puts both notes in the title and the detail. A pair whose notes are `Activa · Engine oil` and `Activa · 5.6 L` must show both notes. The title is not `Two Vehicle expenses on ${date}` alone.

## Group 2 — home

`BOARD_CIRCLE` is `["custom", "money", "travel", "home", "desk", "workshop", "adhd"]`.

`swipeScreens` returns that full list for every preset. `swipeStartIndex` is the opened preset's index. `swipePages` appends a clone of `custom` after `adhd`. Landing on that clone wraps to `custom` with `swipeWrap`. The last board wraps to the first.

`columnsFor` returns `2` for every preset, including `adhd` and a board with one tile. `rowFlex` gives a `size: "large"` card span `2` (a full row). A small card spans `1`. One leftover small card does not stretch across the row: `PresetGrid` in `frontend/src/components/HomeModes.tsx` keeps an empty second column.

`frontend/app/(tabs)/index.tsx` renders `SwipeHome` for every preset, not only money and travel. The `adhd` page renders `AdhdPanel`. Every other page renders `PresetGrid`.

Home date copy uses `dueDayLabel`. A negative day count is `was due N days ago`, zero is `today`, and a positive count is `N days`. Deleting `renderTile` in `frontend/app/(tabs)/index.tsx` removes the home-tile caption that says `late`. The same wording replaces the remaining lines in `frontend/app/home/index.tsx` (`d late`), `frontend/src/components/HomeLife.tsx` (`d late`), `frontend/src/core/intelligence.ts` (maintenance title, chore title, and the maintenance rule sentence that says `urgent once overdue`), `frontend/src/core/rules.ts` (maintenance title `overdue by N days`), and `frontend/src/core/widgets.ts` (`days overdue`). The words overdue, missed, behind, late, and fail are not used in that copy.

A module whose `enabled` is false is removed from `visiblePresetItems` by `withModulesOn`. Tiles with no module (`attention`, and the adhd `next` card) stay. Turning money off hides `balance` and the other money tiles. The `txns` array is unchanged. Turning cycle off hides the cycle tile. `db.cycle` is unchanged.

## Group 3 — travel and money

Public transport is a trip with `mode: "public"` and `transit` of `metro`, `train`, `cab`, or `bus`. The label for `cab` is `Cab or taxi`. A trip with no mode, or `mode: "personal"`, is a personal-vehicle trip and has no transit subcategory. A public fare is an expense with category `Transport` and a note of the transit label. It is not a fuel row and not a vehicle expense.

Weather location:

- `locationPhase` is `ask` until the user has been asked, `read` after they grant and before a fix is stored, and `stop` after a fix is stored or after they decline.
- The app asks once, reads one coarse position, stores `{ lat, lon }` and a `Place`, then does not ask again.
- `CAN_TOGGLE_SYSTEM_LOCATION` is `false`. The screen says the app cannot turn the phone's location switch on or off. No code path sends `ACTION_LOCATION_SOURCE_SETTINGS` or otherwise flips that switch.
- `ACCESS_FINE_LOCATION` stays in `blockedPermissions` in `frontend/app.json`. `ACCESS_COARSE_LOCATION` is removed from that block list so the one coarse read can be granted. Background location stays off.

Money: `grewMost` compares this month with last month for expenses that are not transfers. It returns the category with the largest positive growth, plus the two amounts, and a line `${category} grew the most. ${thisMonth} this month, ${lastMonth} last month.` The return type has no score and no points. If nothing grew, it returns `null`.

Personal vehicle, on the vehicle the user already has:

- `costPerKmLine` formats `vehicleOwnership(...).perKm` as `${amount} per ${unit}` when the number is finite.
- `fuelAgainstTank(litres, tankLitres)` returns a line `${litres} L of a ${tankLitres} L tank`. `Vehicle.tankLitres` is optional.
- `serviceLeftLine(km)` is `${km} km left before service` when `km` is positive, and `${n} km past this vehicle's service interval` when it is not. Replace the user-facing service strings that say `overdue` in `frontend/src/core/intelligence.ts`, `frontend/src/core/rules.ts`, `frontend/app/vehicles/index.tsx`, and `frontend/src/core/search.ts` with this line.

Cycle: `typicalCompare` returns a line only when `cycleLengths` has at least two gaps (two real cycles). The line is `Your typical length is N days. This one is M days so far.` `forecast(...).line` still begins with `Guess` when the forecast is not paused. `forecastDetail` still says the window is a guess. No mood, arousal, food, or remedy copy. `ADHD_VOICE` stays `false`. No spoken buddy.

`receiptMismatchLine` returns `This receipt does not match the bank debit.` when `flagMismatch` is true, and `null` when the amounts match to the cent.

`weatherReminder(saved, alreadySent)` is true only when weather is not saved and the reminder has not been sent. `Trip.weatherReminded` records that one send. `reuseMarkedStops` returns stops marked on a previous trip that are not already on this trip, using the existing `reusableStops` rules.

## Group 4 — cycle dates, gallery, privacy

`rememberPeriod(days, start, end)` writes a `bleeding: "flow"` day for each date from `start` through `end` inclusive, and sets `ended` on the last day. A second call with the same dates does not add a second row per date. `end < start` leaves the array unchanged. The days stay on `db.cycle`.

`galleryShots` collects rows that have a `photo`. `stepGallery` moves to the next or previous shot and wraps. When one image is open (`count === 1`), `swiped` is still `true` and the index stays `0`. `PhotoGallery` uses a horizontal `ScrollView` with `pagingEnabled` and `decelerationRate="fast"`, including while a shot is open.

`frontend/app/privacy.tsx` is a plain screen, linked from Settings → Security & privacy as `Privacy and usage`. It states:

- What stays on the phone: records, photos, bills, and cycle dates, in the encrypted file on this phone.
- What each permission is for: fingerprint or face (unlock), notifications (reminders and the emergency card while that switch is on), notification access (bank lines, codes dropped), photos (a picture the user chooses), location (one reading for weather, then it stops, and the app cannot turn the phone's location switch on or off).
- What never leaves: records, photos, cycle dates, and bank lines stay on this phone. A locked backup leaves only when the user taps Sign in and store this file. Online weather sends the place that was saved, not the rest of the file.
